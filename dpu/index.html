template for: a performance win for streaming SSR

At the same reveal policy React ships today (~300 ms), streaming with <template for> uses less main-thread time than classic Fizz $RC — about 39% less at 60 boundaries and 48% less at 500. A small script fallback matches that win in browsers without native support.

Libraries should emit the platform markers and keep a script fallback. The demos and fork PRs below are worked examples of that shape, not the only API.

Why the platform path is faster

  • Native apply: Chrome applies <template for> as it parses. Less library JS running completion scripts for every boundary.
  • Cheaper fallback: one small script helper for unsupported browsers beats a page-wide MutationObserver once there are hundreds of boundaries.
  • Same policy, less work: holding the reveal window fixed isolates the mechanism. The main-thread savings above are not from revealing sooner.

What libraries should ship

  1. Emit the platform markers — <?start name>…<?end> and <template for>.
  2. Use a per-flush script fallback where native support is missing (the row that wins at 500 and 2,000 above).
  3. Extend the script fallback for hard cases — SVG/MathML, view-transition reveals, and resume/prerender stay on the same markers; cover them with JS / platform fixes, not a second protocol.

Known gaps — cover with JS / script fallback

Do not keep a permanent classic path for these. Keep emitting <template for> + markers, and extend the script / JS fallback (and platform fixes where needed) so one protocol covers them.

  • SVG / MathML: native patching can land the wrong namespace — a DPU-aware script fallback that preserves foreign namespaces (or a platform fix), not hidden-node $RC.
  • View-transition reveals: teach $RP / a thin DPU-side helper to participate in startViewTransition.
  • Resume / prerender: rehydrate the same markers and templates on resume; script fallback applies if native did not.
  • Late styles / SRI: carry attributes through the declarative patch path (and the script fallback) so stylesheet boundaries stay on DPU.
