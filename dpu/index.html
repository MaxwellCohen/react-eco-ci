The case

Libraries that stream Suspense (or equivalent) results into already-parsed HTML should speak the platform wire format — <template for>, <?start>, <?end> — instead of inventing another private script protocol that does the same job.

Chrome 150 ships the feature. The WHATWG HTML change is merged. Mozilla and WebKit both hold positive positions. Frameworks that keep shipping only getElementById + inline mutation scripts will look like they are fighting the platform they depend on.

Scope of this page. This is an adoption argument and a measurement notebook. The linked PRs and Workers demos are worked examples used to pressure-test the argument. They are not a claim that every library must copy one API shape, one bootstrap global, or one flush policy.

What libraries should do

The useful agreement is at the wire and fallback layer. Everything above that — option names, defaults, batching, hydration hooks — can and should differ by library.

  1. Emit the platform markers when streaming out-of-order HTML. Pending ranges use <?start name>…<?end>. Completions use <template for="…">. That is the durable contract with the browser.
  2. Ship a small script fallback for browsers without native support. Prefer an explicit per-chunk (or per-flush) call over a page-wide MutationObserver polyfill once boundary counts get large. Observer polyfills do not scale in the measurements below.
  3. Keep a classic path for known gaps. SVG/MathML namespace patching, view-transition reveals, and some prerender/resume paths still need a library-owned completion today. Falling back is fine; pretending the platform covers everything is not.
  4. Gate the new path while it is experimental. Flag, option, or release channel — libraries should be able to ship without flipping every app overnight.
  5. Compare policies fairly. Do not advertise a latency win that comes only from shortening a deliberate reveal throttle. Hold the window constant when claiming a mechanism advantage.
  6. Do not treat one reference implementation as normative. A React $RP helper, a Preact island observer, a no-server-hold flush, or a 300 ms hold can all be compatible with the same wire format. Pick what fits the library’s streaming model; keep the HTML markers.

Why this is worth doing

1. Platform alignment while feedback still matters

Inline scripts that mutate already-parsed DOM are exactly what the platform is standardising away from. Libraries that emit the new markers now can file concrete gaps (foreign namespaces, declarative batching, patch scope) instead of arriving after the format freezes around other ecosystems.

2. Correctness wins show up before “free speed”

On Preact stream-only checks across Chromium, Firefox and WebKit, main passed 23/26. Template-for branches passed 26/26, including table rows, SVG and MathML. Timing stayed within noise of main. That is a stronger early argument than a latency headline.

3. One shared HTML dialect beats N private protocols

Classic Fizz-style completion scripts and island morph protocols both reinvent out-of-order HTML. The platform now has a name for that job. Interop, tooling, and browser investment all get easier if libraries converge on the markers even when their JS fallbacks differ.

4. Honesty about performance

An earlier “3 ms vs 124 ms” patch-lag comparison mixed declarative streaming with a shorter reveal policy than shipping classic $RC’s ~300 ms client throttle. That is a policy change, not a mechanism win. Fair tables below hold the window constant — and separately show a no-hold arm for people who want that design.

Open risks (stated plainly)

  • SVG / MathML: native patching can produce the wrong namespace / no box. Routing those boundaries through a classic completion is a reasonable library policy and concrete spec feedback.
  • Late styles / stylesheets: where patches write styles at the boundary, SRI and related attributes may not survive every path yet.
  • Injection: predictable boundary names can be targeted by attacker HTML. Classic getElementById completions already share that class. DPU can apply with scripts blocked. Patch scope (parent-only vs document-wide) needs a clear answer from the platform.
  • Hydration races: markers should remain until </template> arrives; each implementation still needs verification on real Chrome.
  • View transitions on reveal: native patches cannot enter startViewTransition; those boundaries stay classic unless the platform grows a hook.

Spec / browser feedback worth filing

  1. Foreign-namespace patching (SVG/MathML) should produce elements in the right namespace without a serialize/reparse.
  2. There is no declarative way to batch or delay reveals; frameworks that care about popcorn CLS have no native lever once the server stops holding.
  3. Clarify whether a <template for> only patches descendants of its parent, or any range in the document — the security story depends on it.
