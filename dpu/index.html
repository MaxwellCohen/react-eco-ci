Declarative Partial Updates for streaming SSR: Preact and React results

Evidence for how preact-render-to-string and React Fizz can stream Suspense completions with DPU (<template for>, <?start>). Chromium, Firefox and WebKit via Playwright, one machine, one day. Test pages, harness and write-ups were produced with Claude (Anthropic) via Claude Code, directed by the repo owner. Scenario expectations are proposals to review, not ground truth.

Headline.
  • Preact: any DPU variant fixes real main bugs (table rows, SVG/MathML namespaces): 26/26 vs 23/26 checks with no client JS. PR #474 as opened has two defects (a foreignObject main-thread hang; the last boundary lost in Firefox/WebKit when hydration starts right after the stream). No timing penalty otherwise; +3 to +6 gzip bytes per boundary.
  • React Fizz: the DPU branch passes all 28 checks stream-only in Chromium (native, $RP fallback and polyfill with native support disabled), Firefox and WebKit. Remaining hydrate=late failure (nested-template) also fails on the baseline, so it is not DPU-related.
  • Open for standards discussion: strict CSP in non-native browsers (inline fallback scripts carry no nonce), and the cost of repeating boundary ids across marker systems.

Defects in PR #474 as opened (reproducible with /s/foreign-object and /s/popcorning): a boundary inside <svg><foreignObject> freezes the page in all three browsers; in Firefox and WebKit the last streamed boundary is missing when hydration runs right after the stream. Cause not root-caused (hypothesis: race between the final patch and observer teardown). Why main compresses better: the boundary id is written more times (3 vs 4 to 5), each extra copy costing ≈2.9 gzip bytes; see the full report.

React Fizz: declarative patching in Firefox and WebKit

Fixture flight-ssr-bench at React commit 71111fb9b4 (branch fizz/declarative-patching), the 26 Preact checks ported plus 2 React-only (x-css-precedence, x-style-precedence), and an isolated foreignObject page. Browsers: Chromium 156.0.8078.4, Firefox 157.0, WebKit 27.2 (Playwright). Variants: baseline ($RC), decl-native (Chromium DPU), decl-$RP (DPU markup, $RP script fallback), decl+polyfill (template-for polyfill). In Chromium, native DPU was disabled with --disable-blink-features=DocumentPatching to exercise the fallbacks.

Lag of 120 to 180 ms here is dominated by the Fizz declarative batching window (unstable_declarativeBatchMs, default). With batchMs=0 every variant, including $RP and the polyfill, shows 1 to 3 ms median lag in all three browsers (e.g. Firefox decl-$RP-b0 2 ms, decl+polyfill-b0 2 ms; WebKit 1 and 2 ms). So the $RP fallback and the polyfill add no measurable cost beyond batching. "Last visible" differences of ~300 ms between rows reflect which boundary batch landed last and are within the batching granularity. Popcorning (16) and grid-100 (100) results are in results.md.

Method and limitations

  • Correctness: 26 checks (+2 for React), hydrate=off judges stream/polyfill alone; late runs after hydration and can mask failed patches.
  • Timing: 5 iterations, variants interleaved in random order; patch lag via MutationObserver plus a 16 ms layout scan, so resolution is about 16 ms. Differences under that are noise.
  • One machine, local server for React (deployed Workers for Preact), no throttling or real wire compression. Not measured: low-end CPU, >100 boundaries, bfcache, buffering proxies.
  • Preact variants local-end-stamp and local-react-style in the full report come from unpushed commits.
  • Strict CSP with inline fallbacks is unsolved by every variant in browsers without native DPU.
