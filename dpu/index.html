template for: a case for streaming libraries

Libraries that stream Suspense (or equivalent) results into already-parsed HTML should use the platform wire format — <template for>, <?start>, <?end> — with a small script fallback where native support is missing.

Chrome 150 ships it. The WHATWG change is merged. Mozilla and WebKit positions are positive. The linked demos and PRs are worked examples of that approach, not a requirement to copy one API or flush policy.

What libraries should do

Agree on the wire and a fallback. Differ on options, defaults, and scheduling.

  1. Emit the platform markers. Pending ranges: <?start name>…<?end>. Completions: <template for="…">.
  2. Ship a small script fallback for browsers without native support. Prefer a per-flush call over a page-wide MutationObserver once boundary counts get large — the script path stays cheap at scale in the measurements below.
  3. Keep a classic completion for known gaps (SVG/MathML, view-transition reveals, some prerender/resume). Preferring DPU does not mean every boundary must use it.
  4. Gate while experimental — flag, option, or release channel — so apps can adopt without an overnight default flip.

Why it is good

Platform work instead of a private protocol

Out-of-order HTML patching is now a browser feature. Libraries that emit the markers get native application in Chrome today, a clear fallback story elsewhere, and a seat at the table for remaining gaps (foreign namespaces, declarative batching, patch scope).

Real correctness wins

On Preact stream-only checks across Chromium, Firefox and WebKit, main passed 23/26. Template-for branches passed 26/26, including table rows, SVG and MathML, with timing within noise of main.

Less main-thread work at shipping-like policy

When the reveal window matches a classic ~300 ms policy, native DPU and a script fallback both cut Chromium main-thread task time versus classic $RC — about 39% at 60 boundaries and 48% at 500. That is the comparison that matches how React ships today.

One HTML dialect across libraries

Fizz-style completion scripts and island morph protocols both reinvent the same job. Converging on <template for> makes interop, tooling, and browser investment easier even when JS fallbacks differ.

Known gaps (keep a classic path)

  • SVG / MathML: native patching can land the wrong namespace; route those boundaries through a classic completion and file platform feedback.
  • View transitions on reveal: native patches cannot enter startViewTransition yet.
  • Late styles / SRI: some attribute carry-through still needs library care on the declarative path.
  • Spec clarity: foreign-namespace patching, declarative batching, and whether template for is parent-scoped vs document-wide are worth filing.
