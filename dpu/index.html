The ask

Adopt <template for> for out-of-order streaming SSR, behind a flag, with the smallest possible delta over today’s $RC / island protocols.

Chrome 150 ships the feature. The WHATWG HTML change is merged. Mozilla and WebKit both hold positive positions. Frameworks that keep inventing private script protocols will look like they are fighting the platform they depend on.

Why this is worth doing

1. Platform alignment while the door is open

React’s explainer-cited pattern — inline scripts that mutate already-parsed DOM — is exactly what the platform is standardising away from. Adopting the wire format now means React and Preact can send feedback that shapes the remaining gaps (SVG namespaces, declarative batching) instead of arriving after the fact.

2. Real correctness wins in Preact today

On stream-only checks across Chromium, Firefox and WebKit, main passes 23/26. The template-for branches pass 26/26, including table rows, SVG and MathML. Timing stays within noise of main.

3. One bootstrap instead of one script per boundary

Classic Fizz emits a completion script for every boundary (or group). Declarative streaming writes ranges and templates; unsupported browsers get a single $RP helper (about 921 B raw / 523 B gzip) instead of inventing a second protocol.

4. Honesty about speed

The earlier “3 ms vs 124 ms” patch-lag headline compared a short declarative hold to classic $RC with its deliberate 300 ms client throttle. That is a policy change, not a mechanism win. Fair comparisons keep the window constant.

What to ship

React — one PR

MaxwellCohen/react#25 consolidates the stack into a single commit on the fork (enableFizzDeclarativePatching, off in every published build):

  • Wire format: <?start name>…<?end> + <template for>
  • One $RP fallback for browsers without native support
  • No server-side hold — completed boundaries flush on the next normal flush
  • Classic path kept for SVG/MathML, ViewTransition, prerender/resume
  • Predictable names kept (same class as today’s S: / B: ids) — unguessable prefixes are optional hardening, not required for parity
<!--B:0--><!--$?--><?start name="B:0">Loading…<?end><!--/$-->
<!-- later -->
<template for="B:0">…content…</template>
<script>$RP("B:0")</script>

Preact — opt-in on top of #474

MaxwellCohen/preact-render-to-string#8 answers the maintainer request: dpu: true on the stream APIs, marker checks before applying a template, observer scoped to document.body. Default stays <preact-island>. Upstream #474 / #490 are untouched.

Costs of the simple design

  • No client throttle with native support. The browser applies a template as it parses it. There is no hook to batch reveals. Unsupported browsers could throttle in $RP; leaving that out keeps both paths aligned and simpler.
  • Main-thread win at 300 ms does not automatically transfer to the no-hold design. Treat “faster” as conditional until the no-hold arm is published alongside this page.
  • Polyfills are a trap at scale (1.7 s main-thread at 2,000 boundaries). Ship a script fallback, not a MutationObserver polyfill, for React.
  • Gzip is not a win on small pages. Argue platform + correctness first.

Open risks (stated plainly)

  • SVG / MathML: native patching produces XHTML elements with no box. React routes those boundaries through $RC. This is also concrete feedback for the spec.
  • Late styles / stylesheets: declarative patches write them at the boundary; SRI and related attributes are not preserved on that path yet.
  • Injection: predictable names can be targeted by attacker HTML. Classic $RC already has the same class via getElementById. DPU can apply with scripts blocked. Nested templates did not patch foreign ranges in Chromium experiments; body-level templates can.
  • Hydration race: not reproduced at the platform level — markers remain until </template> arrives — but the React branch itself still needs a real Chrome verification on this head.
  • View transitions on reveal: native patches cannot enter startViewTransition; those boundaries stay classic.

Spec / browser feedback worth filing

  1. Foreign-namespace patching (SVG/MathML) should produce elements in the right namespace without a serialize/reparse.
  2. There is no declarative way to batch or delay reveals; frameworks that care about popcorn CLS have no native lever once the server stops holding.
  3. Clarify whether a <template for> only patches descendants of its parent, or any range in the document — the security story depends on it.
