Archived run. Measured on earlier fork branches (fizz/1…4, with a server-side batching hold) that are now consolidated into MaxwellCohen/react#25, which has no hold and keeps SVG/MathML on $RP. “decl+polyfill” here is the MutationObserver variant. Current case and numbers: template for case page.

The batching fix

With the old 300 ms default hold, patch lag at default settings was 120 to 180 ms median and about 300 ms at p95, no better than the script baseline. The default hold is now one animation frame (16 ms). An explicit unstable_declarativeBatchMs still works as a throttle window. With the fix, every DPU variant in every browser sits at 2 to 4 ms median lag (p95 4 to 11 ms). The $RC baseline is unchanged at about 110 to 175 ms because it still uses the client-side throttle.

Notes

  • One check, nested-template, fails after hydration for every variant including the baseline, so DPU is not the cause.
  • While the document is loading, the MutationObserver applies a patch only if the template already has a following element. The $RP script provides that automatically. On fizz/3-suspense-batching, which has no $RP, each patch was applied one patch late, which looked like 1 s of lag on sparse pages. That is a MutationObserver-fallback limit, not a Fizz bug.
  • One machine, local server, no throttling or real wire compression. Brotli sizes were not measured.
