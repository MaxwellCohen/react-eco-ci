Merge PR #24, turn on enableFlightHtmlFirst — no framework side channel required for in-process Flight→SSR. Compared with stock React main (same tip, flag off):

  • ~43% smaller gzip HTML downloads across 41 pages (sum)
  • ~79% less inlined Flight (the JS payload in the document)
  • No Waku throughput win on tip (fresh host-row ≈ 1.02×, within noise) — Flight not shrinking under Waku’s tree today

Authors keep the same components and APIs. Correct pages hydrate and interact like stock. The correctness corpus at this tip is 41/41 in Chromium — including head-hoistables (registry SSR applies Flight :HL preload hints into Fizz).

What changes

One experimental flag. Static Server Component host markup in host position (including Suspense children and Client Component children) is left out of the browser Flight payload and adopted from SSR HTML. Non-children props stay in the payload. In-process SSR claims elided rows from React's internal registry (stream :Q id); frameworks do not pass onElidedRow / elidedRows. Optional onElidedContentMissing recovers if a stub mounts without server DOM. SPA navigation / refetch must use onElidedRow: false for a full Flight payload that adopts existing DOM.

Nothing changes for apps until the flag is on. Authors keep writing the same components.

Correctness (UX / DX)

  • Same public component model: authors do not mark trees or change JSX for the win.
  • Hydration adopts server DOM for elided regions; interactive client islands keep working.
  • 41-page corpus: Chromium at tip is 41/41 (including head-hoistables after the registry :HL flush fix). DOM compare also canonicalizes style spacing / zero-length CSS units / attribute order.
  • Deferred mounts (modal, ClientOnly) and Suspense client-render recover via framework-supplied onElidedContentMissing (without it, stubs suspend and report rather than blanking quietly).
  • Head DOM is not always byte-identical under zero-optin; unique resources still match.

How it works

Today an RSC initial response ships the same static server markup twice: Fizz HTML to paint, and an inlined Flight payload to hydrate. With enableFlightHtmlFirst, React withholds static Server Component host trees that sit in host position (direct host children, including inside Suspense and as Client Component children) from the browser Flight stream. Non-children props stay in Flight so client components keep full props and hydrate normally.

With the flag on, React auto-elides into an internal registry keyed by a :Q row in the stream. The first in-process createFrom* claims it for SSR; the browser isolate has an empty registry and adopts HTML. Explicit onElidedRow / onElidedValue remain for out-of-process sinks. Optional onElidedContentMissing recovers if a stub would otherwise mount without server DOM (deferred mounts, mismatch remounts).

SPA navigation/refetch must pass onElidedRow: false for a full Flight payload (auto-elision would leave stubs with no HTML). Elided stubs use the same host tag as the full payload, so react-dom adopts the existing DOM on navigation (hydrates real children into the static island) instead of creating new nodes when the tag matches.
