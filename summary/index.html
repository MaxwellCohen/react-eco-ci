HTML-first React: Results Summary

Merge PR #24 or a similar feature of, turn on enableFlightHtmlFirst, and having the framework opt into it. Compared with stock React main (same tip, flag off):

  • ~43% smaller gzip HTML downloads across 41 pages (sum)
  • ~79% less inlined Flight (the JS payload in the document)
  • ~3× server requests/sec on a patched framework host-row page (measured in Waku)

And no impact on user experience or developer experience: same components, same hydration behaviour for correct pages, same APIs for authors. That is what the correctness corpus is for — 41/41 pages pass in Chromium, Firefox, and WebKit after the position, Suspense, and children rules landed.

What changes

One experimental flag. Static Server Component host markup in host position (including Suspense children and Client Component children) is left out of the browser Flight payload and adopted from SSR HTML. Non-children props stay in the payload. Frameworks pass onElidedRow / elidedRows; optional onElidedContentMissing recovers if a stub mounts without server DOM.

Nothing changes for apps until the flag is on and the framework opts in. Authors keep writing the same components.

Throughput vs stock

With the flag on and a framework opted in (host-row 1000-row page): 3.19× requests/sec vs stock React (about +219%), TTFB about half. Client-row pages save bytes but timing stays within noise. Flags on without framework opt-in do not move gzip and are not the proposal.

Waku is the measurement vehicle here — chosen because it is easy to patch and has strong RSC support — not because the win is Waku-specific. Any framework that wires onElidedRow / elidedRows (and optional recovery) should see the same class of result.

In-process Flight→Fizz render time across the 41 pages sums to about 1.30× less work (~+30% render throughput proxy) on a shared laptop — directional only; prefer the framework side-by-side numbers for server capacity.

No UX / DX impact (correctness)

  • Same public component model: authors do not mark trees or change JSX for the win.
  • Hydration adopts server DOM for elided regions; interactive client islands keep working.
  • 41-page corpus in Chromium, Firefox, and WebKit: 41/41 pass (DOM compare now canonicalizes zero-length CSS units so remount 0px matches server 0).
  • Deferred mounts (modal, ClientOnly) and Suspense client-render recover via onElidedContentMissing without blanking the page.

How it works

Today an RSC initial response ships the same static server markup twice: Fizz HTML to paint, and an inlined Flight payload to hydrate. With enableFlightHtmlFirst, React withholds static Server Component host trees that sit in host position (direct host children, including inside Suspense and as Client Component children) from the browser Flight stream. Non-children props stay in Flight so client components keep full props and hydrate normally.

Elision only runs when the framework opts in. React needs a side channel: the server passes onElidedRow (JSON) or onElidedValue (live node for in-process SSR) so SSR still receives the markup and emits it as HTML; the client passes elidedRows so hydration adopts those DOM nodes instead of expecting them in the inlined payload. Optional onElidedContentMissing recovers if a stub would otherwise mount without server DOM (deferred mounts, mismatch remounts). The flag alone does nothing — without that handoff, withholding content would mean blank HTML or broken hydration.

Initial load only: navigation/refetch responses are ordinary full Flight. Elided stubs use the same host tag as the full payload, so react-dom adopts the existing DOM on navigation (hydrates real children into the static island) instead of creating new nodes when the tag matches.
